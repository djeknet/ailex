# API Key Encryption

## Обзор

Расширение использует шифрование AES-GCM для защиты API ключей, хранящихся в `chrome.storage.sync`.

## Реализация

### Файл: `src/shared/utils/encryption.ts`

**Алгоритм:** AES-GCM-256  
**Генерация ключа:** PBKDF2 с 100,000 итераций  
**Соль:** Комбинация статической соли + `chrome.runtime.id`  
**IV:** 12 байт случайных данных для каждого шифрования  

### Функции:

#### `encryptApiKey(apiKey: string): Promise<string>`
Шифрует API ключ и возвращает Base64-строку.

#### `decryptApiKey(encryptedKey: string): Promise<string>`
Расшифровывает Base64-строку обратно в API ключ.

#### `isEncrypted(value: string): boolean`
Проверяет, является ли строка зашифрованной.

## Интеграция

### `settingsStore.ts`

**При сохранении (`updateOperators`):**
```typescript
const encryptedApiKey = op.apiKey ? await encryptApiKey(op.apiKey) : '';
// Сохраняется в chrome.storage.sync
```

**При загрузке (`initializeSettings`):**
```typescript
const decryptedApiKey = op.apiKey ? await decryptApiKey(op.apiKey) : '';
// Используется в памяти приложения
```

## Безопасность

1. ✅ **Шифрование в хранилище** - API ключи зашифрованы в `chrome.storage.sync`
2. ✅ **Уникальный ключ для расширения** - Использует `chrome.runtime.id` как часть соли
3. ✅ **Случайный IV** - Каждое шифрование использует новый IV
4. ✅ **Обратная совместимость** - Если расшифровка не удалась, возвращается оригинальная строка

## Ограничения

⚠️ **Важно:** Этот метод защищает от просмотра ключей в storage inspector, но не защищает от:
- Вредоносных расширений с доступом к памяти
- Дебаггера/инспектора во время выполнения
- Экспорта расширения с последующей расшифровкой

Для полной безопасности рекомендуется использовать server-side прокси.

## Миграция

При первой загрузке после обновления:
- Старые незашифрованные ключи будут корректно обработаны
- При следующем сохранении они будут зашифрованы автоматически
