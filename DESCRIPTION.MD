**Описание проекта “AiLex”**

**Общее описание:**

Браузерное расширение в виде чата с ИИ, которое открывается в sidepanel, и в котором можно подключить на выбор оператора: OpenAI, Anthropic, OpenRouter, Local LM, Grok, Gemini, просто указав свои API ключ.

Расширение имеет настроенные инструменты, которые позволяют ИИ взаимодействовать со страницей, получать определенную информацию, или производить изменения на странице, заполнять формы и тд.

**Функционал расширения:**

- Чат, в котором можно задавать вопросы или команды (инструменты) для выбранного ИИ  
- История диалога может фиксироваться для всех сайтов общая или для каждого сайта - отдельная  
- Настройки расширения с табами:   
Операторы:
1. Указание API ключей для ИИ операторов с тестированием подключения, выбор модели из списка загруженных по api. Загруженные модели кэшируются в local storage, чтобы в дальнейшем в самом чате выводить список этих моделей, без апи запроса к оператору. Список операторов: OpeanAI, Anthropic, OpenRouter, Grok, Gemini, LM Studio (локальный оператор). Рядом с каждым оператором выводится лого, которое находится в папке 'icons/ai', эти же иконки используются в селекте с выбором модели над полем сообщения, а также отображаются в самом ответе от ИИ, чтобы визуально сразу было понятно от какого ИИ был ответ.

Общие:
1. Тема: системная, темная, светлая  
2. Язык
3. Сохранение диалога: для всех сайтов (по умолчанию), для каждого сайта, в рамках сессии. В рамках сессии - означает, что история диалога будет удалена после закрытия расширения, при этом ни как не меняется при переключении между вкладками. Для всех сайтов - история диалога общая для всех сайтов и ни как не меняется и не обновляется при переключении между вкладками браузера. Для каждого сайта - будет подгружаться история диалога в зависимости от сайта активной вкладки, то есть при переключении вкладки браузера история диалога будет динамически обновляться.
4. Ручное удаление всей истории диалогов по красной кнопке  "Удалить историю диалогов", с подтверждением в модельном блоке.

Формы:
1. Личная информация: заполняется список полей с различной личной информацией, которая затем будет использоваться для автоматического заполнения форм на сайтах: имя, фамилия, email, телефон, страна, город, адрес, zip, соцсети, должность, о себе.

Инструкции:
1. "Общая инструкция" - указывается системная инструкция, которая добавляется в начале каждого диалога с ИИ, если нет инструкции для конкретного сайта.
2. "Подключаемые инструкции", с кнопкой "Добавить инструкцию", открывает диалоговое окошко с  3 полями:  Название (input), Домен (input) и Инструкция (textarea), и кнопкой "Добавить" (неактивна, пока не заполнены оба поля). Список промтов выводится в виде названия, при клике на которой выводится то же самое диалоговое окошко но уже для редактирования данных и кнопкой "Сохранить". Далее при общении с чатом, если для текущего активного сайта указана инстркция, то она будет автоматически выбираться в селекте с инструкциями рядом с кнопкой отправки сообщения.

- Прикрепить скриншот - рядом с полем для ввода сообщения есть кнопка “прикрепить скриншот”, при нажатии на которую активируется селектор для выбора зоны для скриншота. Экран темнеет, а выбранная зона - без затемнения, и после выбора, картинка подставляется в поле чата, то есть визуально отображается небольшая квадратная картинка выбранной области.  
- Список инструментов - запрограммированный список с описанием для ИИ что делают эти инструменты и как с ними работать. Также ИИ в своих ответах может возвращать весь список этих инструментов или какие-то конкретные в виде кнопок, пользователю нужно нажать, выполнить инструкции от ИИ, если требуется и получить результат использования инструмента. Каждый инструмент - это отдельный сервис, в отдельном файле в папке tools.
- Выбор инструкции по кнопке, которая выводит список инструкций. При выборе инструкции она отмечается в списке, а кнопка становится зеленой. можно отменить выбор, выбрав в списке "Без инструкции". Если инструкция выбрана, то она будет отправлена вместе с сообщением пользователя как system.
- Ответ от ИИ с результатами может содержать: текст, файл (картинка, pdf, json, html, txt, csv, zip). Для файлов используются подключенные сторонние библиотеки, скачанные и встроенные (никаких внешних ссылок на библиотеки).

Все настройки расширения хранятся в sync storage.

**Структура:**

Чат (Chat):

- При клике на иконку расширения открывается чат в sidepanel браузера. Для нового чата, поле ввода сообщения с элементами управления выводится по середине. Если же есть история диалога, то большую часть занимает поле с сообщениями от пользователя и ответами от ИИ (со скроллом). Ниже textarea для ввода запроса, который можно отправить по Enter, и с элементами управления.  
- Есть header, где отображаются кнопки: “История чатов”, “Новый чат”, “Закрыть чат”. 
- Над textarea  выводится маленький select со списком настроенных операторов и моделей. Селект должен быть стилизованным с разделением по группам, где каждый оператор - это группа внутри которой список доступных моделей. Также рядом с каждой моделью и оператором выводится логотип оператора. Это должен быть красиво оформленный список. После выбора модели, название модели и лого отображается в селекте.  
- Справа от выбора модели кнопка “Прикрепить скриншот” - при клике активируется выбор зоны для скриншота.  
- Под textarea кнопка “Отправить” на 100% ширину.  \
- Toggle кнопка "[site icon] Текущая страница" - активирует передачу контекста текущей страницы вместе с сообщенеим пользователя. Справа у кнопки кнопка "▾" (Button Group) для вывода dropdown меню с опциями: "Только текст", "DOM страницы", "HTML страницы" - в зависимости от выбранного типа будет отправляться либо текст страницы из body без HTML, если же выбран DOM - то полный код страницы, HTML - исходный код. По умолчанию выбран "Только текст". По умолчанию в новом чате кнопка активна (подсвечена), если нажать на нее, то передача контекста отключается (подсветка убирается). Вместо "[site icon]" - выводится иконка сайта.
- Сообщение от пользователя выводится классически справа в выделенном фоном блоке, а ответы от ИИ - слева без фона.  
- Под ответами от ИИ выводятся кнопки: Копировать - при наведении выводится dropdown с выбором вариантов копирования: Копировать с форматированием, Копировать без форматирования, Копировать в буфер. Переписатьи (выводится только для последнего ответа в чате)  - при клике выводит список actions для ответа ИИ: Сделать длиннее, Улучшить письмо, Сделать короче, Упростить язык, Перефразировать. При выборе экшена в чат подставляется сообщение с ссылкой на выбранное сообщение и отправляется в ИИ. Также выводится иконка ИИ оператора, при наведении курсора на которую выводится дропдаун с заголовком “Сравнить ответы” и далее список подключенных моделей, а текущая модель ответа выделена фоном и галочкой “check”. При клике на другую модель из списка, в чат отправляется прошлый запрос пользователя но уже в другую модель (оператор), и таким образом мы можем сравнить ответы от разных ИИ.  
- Сообщения в чате обрабатываются Markdown конвертером в HTML тэги. А также есть поддержка тэга code с выделением содержания при двойном клике на блок.

В футере расширения иконки в ряд для переключения между вкладками-страницами расширения:

- Chat - страница с чатом.  
- Settings - Страница с настройками.  
- History - история диалогов по дням, сайтам.  
- Help - страница с описанием функционала расширения.  
- Tools - страница с настройками собственных инструментов для ИИ.

**Логика:**

При первом открытии расширения или при попытке открыть чат, пока не настроен ни один ИИ оператор с выбранной моделью, по умолчанию открывается страница настроек, где над списком ИИ операторов выводится подсказка в выделенном оранжевом блоке: 

“Для начала работы с чатом необходимо подключить хотя бы одного ИИ оператора и выбрать модель, для этого укажите свой API ключ (если необходимо) для выбранного и нажмите Тест”

При тесте отправляется запрос на API выбранного оператора, и только после того, как тест был пройден успешно, api ключ сохраняется в sync storage в виде массива или объекта: [operator: {key: api, model: model, endpoint: url, models: url}]. Так как у нас будет еще локальный оператор, для которого также нужно будет указать endpoint для обращения к ИИ и к списку моделей.

После успешного подключения ниже ключа подгружается список доступных моделей оператора, по умолчанию в селекте “Выберите модель”, после выбора модели значение сохраняется в model. А сам список моделей кэшируется в local storage.

После выбора модели подсказка о необходимости подключения оператора сменяется на зеленый блок:

“Вы успешно подключили своего первого ИИ оператора NAME с MODEL, теперь можете перейти в чат”

И внизу над иконкой чата появляется подсказка в виде tooltip: “Нажмите сюда”.

Такая подсказка выводится только если ранее в кэше не было записей с указанной model, то есть только один раз.

Когда пользователь переходит в чат, если это первое сообщение в чате, то первым выводится системное сообщение с содержанием:

“Задайте вопрос или выберите что хотите сделать  
[tool 1] 
[tool 2]
[tool 3]”

Где вместо tool - выводятся названия инструментов в виде кнопок для быстрого вызова инструмента. У каждого инструмента своя иконка.

Некоторые команды сразу запускают задачу, а другие вызывают диалог ИИ для уточнения деталей.

При этом, при выборе команды из списка - ее название отправляется в чат от лица пользователя.

Список команд:

- Саммари страницы - при клике ИИ собирает весь контент со страницы и создает короткое саммари по нему и присылает в чат.   
- Собрать контакты - ИИ уточняет: Вам нужны все контакты или определенный тип: email, телефон, telegram? - Пользователь отвечает - ИИ уточняет в каком формате вернуть список контактов: текст, JSON, CSV? - Пользователь отвечает - ИИ получает весь body контент страницы и парсит нужные данные и далее вызывает инструмент, который выдает ответ в файле запрошенном формате. И возвращает ответ в чат с сообщением об успешной обработке команды и ссылкой на файл в виде кнопки для скачивания с названием в виде: “домен - тип контактов-дата.формат“ где точка заменена на “_”. Например: “✅ Я успешно собрал все email со страницы. Всего найдено: 10 шт. Скачать файл example_com-email-24_09_2025.txt ”  
- Заполнить форму - кнопка активна, если заполнены поля с личной информацией в настройках, иначе кнопка не активна и при наведении на нее курсора выводится тултип: “Заполните личную информацию в настройках”. При отправке этой команды, ИИ получает информацию о пользователе из базы, далее получает список полей и заполняет их по ассоциациям.

В ИИ при каждом сообщении от пользователя также передается вся текущая история переписки, чтобы ИИ всегда знал контекст.

Общение с ИИ будет в режиме стриминга, то есть ответы от ии должны выводиться с эффектом печати. Единый сервис и метод для всех операторов, где уже в зависимости от выбранного оператора и модели формируется api запрос с нужными параметрами и endpoint.

Также при любом взаимодействии со страницей: парсинг, заполнение полей и тд, на страницу накладывается эффект в виде подсветки краев экрана зеленым цветом, чтобы было понятно, что происходит взаимодействие со страницей в данный момент, также внизу сайта выводится зафиксированная кнопка “Остановить обработку”, при нажатии на кнопку все процессы останавливаются и эффект убирается. Таким образом мы можем прервать обработку в любой момент и при этом в чат в виде ответа от ИИ добавляется сообщение "Операция была прервана пользователем".

**База:**

Для хранения истории диалогов используется IndexedDB:

 Таблица chats - где хранятся чаты, куда записывается:

- время создания  
- время обновления  
- название чата (берется из первого сообщения пользователя, обрезанного до 100 символов)  
- id папки - если чат добавлен в папку  
- site - домен сайта, на котором был создан чат. И если в настройках привязки истории диалога выбрано “по сайтам”, то соответственно мы ищем последнюю запись где текущий домен сайта == site и выводим ее в чате при открытии расширения на этом сайте.

Таблица folders - список созданных пользователем папок чатов: id, дата создания, название.

Таблица history - история переписки и ответов от ИИ:

- время создания  
- id чата  
- user - true, если это запрос от пользователя  
- оператор ИИ  
- модель ИИ  
- reply to - id сообщения на которое ответ  
- text - текст сообщения  
- tokens - количество затраченных токенов на ответ от ИИ (input + output), по умолчанию 0
- file_data - base64 файла (скриншота, или созданного файла от ИИ который можно скачать из истории диалога)

Таблица statistics - для статистики общения с ИИ  по дням, куда записывается:

- дата
- оператор
- модель
- общее количество использованных токенов
- input_tokens
- output_tokens
- количество сообщений


Для работы с базой создать единый сервис, который будет использоваться везде. Также работа с базой должна происходить через [background.js](http://background.js), чтобы сохраненные данные не были привязаны к сайту, а к самому расширению.

**Локализация:**

Для примера добавлен файл хука из другого расширения 'useTranslation.ts' для работы с языком расширения, с автообновлением текста при изменении языка в настройках. В компонентах строки прописываются через функцию 't('type_name')', с автогенерацией списка типов по команде 'npm run i18n:types'. То есть после каждого добавления типов в языковые файлы messages.json дополнительно нужно добавить их в types.ts, чтобы они не подсвечивались в коде.
